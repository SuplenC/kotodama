# kotodama-hyprland code map

A Bundled extension. Maintained by hand: fix stale lines when you find them, and update this map in the PR that adds, moves or renames a module here. Paths are relative to `src/`. `manifest.toml` declares it; `src/main.rs` runs the protocol loop on `kotodama-extension`: an `events` thread waits for Hyprland, follows its event socket, and waits again once it exits, and the windows and the binds each go out through a `SentItems::publish` of their own, so a window event sends only that window. Outside Hyprland it sends no Items, and says it can't do anything (`SentStatus`) until Hyprland runs. See also the [root map](../../CODEMAP.md) and [GLOSSARY.md](../../GLOSSARY.md).

- `hyprland.rs`: `Hyprland::candidates` (the instance `HYPRLAND_INSTANCE_SIGNATURE` names, then every other in `$XDG_RUNTIME_DIR/hypr/`, newest first), `connect` (the first whose event socket answers), `wait` (until one runs, on `kotodama_extension::runtime::wait_for`), `request` (one `.socket.sock` request, as `hyprctl` writes it), `dispatch`, `events`, `language` (`Language`: hyprlang or Lua, from `j/status`, asked once per instance since Hyprland picks it at start), `wayland_socket` (from `hyprland.lock`); `Error` (why Hyprland was not found or refused); `Events::next_change` (`.socket2.sock` lines).
- `events.rs`: `Change::parse` (the events that change an Item: `openwindow`, `closewindow`, `movewindowv2`, `windowtitlev2`, `configreloaded`, and `activelayout`, after which the keys of binds on a keycode are named again).
- `windows.rs`: `Windows` (`from_clients` for `j/clients`, `apply`, `items`), `dispatch` (what each window Action runs: a hyprlang dispatcher, or an `hl.dsp` function under Lua), `ParseError`, `DispatchError`; `FOCUS`, `CLOSE`, `MOVE`, `FLOAT`, `WORKSPACE`.
- `binds.rs`: `Bind`, `parse` (`j/binds`), `ParseError`, `items` (binds with a description), `view` (the Shortcuts View, grouped by modifier), `find`, `shortcuts_item` (what `--view hyprland/shortcuts` names), `keycodes_from_listing` (a Lua bind's keycode, which `j/binds` drops, from the plain listing), `name_keys` (a keycode bind's key under the current layout); `Bind::dispatch` runs a Lua bind's function from the Lua registry; `RUN`, `OPEN`, `VIEW`, `KIND`.
- `lua.rs`: `string`, a Lua string literal for any text.
- `keymap.rs`: `Keymap` (the keycodes and keysyms of an xkb text keymap, parsed by hand, without libxkbcommon; a keysym written as a number is named by its character or a short table), `active_layout` (the main keyboard's layout in `j/devices`).
- `keyboard.rs` (Linux): `keymap`, the keymap Hyprland hands Wayland clients, fetched over its Wayland socket on a thread of its own with a timeout.
- `../tests/fixtures/`: `hyprctl binds -j` and `clients -j` output and an event stream, in Hyprland's formats; under Lua, `binds -j`, the plain `binds` listing and `status -j` (`*-lua.*`, `status-hyprlang.json`); `devices -j`; `keymap.xkb`, a `us,fr` keymap from `xkbcli-compile-keymap`, not pretty-printed, as Hyprland sends it. `../tests/binds.rs`, `../tests/windows.rs`: parsing, grouping, events, Lua dispatches and keycode names against them; unit tests in `hyprland/tests.rs`, `keymap/tests.rs`, `lua/tests.rs`. `../tests/extension.rs`: the Extension over stdio against a fake Hyprland serving both sockets, with a hyprlang or a Lua config, without Hyprland, one that starts after the Extension, and one that restarts.
- `../../../nix/tests/hyprland.nix`: the live tests, in a NixOS VM running Hyprland.
