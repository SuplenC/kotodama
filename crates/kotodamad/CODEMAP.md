# kotodamad code map

The Daemon. Maintained by hand: fix stale lines when you find them, and update this map in the PR that adds, moves or renames a module here. Paths are relative to `src/`; a module's unit tests are in `<module>/tests.rs`, integration tests in `tests/`, benches in `benches/`. See also the [root map](../../CODEMAP.md) and [GLOSSARY.md](../../GLOSSARY.md).

- `lib.rs`: `start` (loads the config from `paths::config_dirs`, reads `[paths]`, then calls `run`), `Error` (why it couldn't start), `run` (wires paths, config, discovery, watchers, server and the main loop; the log level from `[log]` unless `KOTODAMA_LOG` pins it; on a config reload, `watch_extensions` moves the Extension watcher when the Extension dirs change, and `warn_of_restart_keys` logs the `[paths]` keys read only at start); `watch_programs`, the `programs` watcher on the directories `Daemon::failed_programs` names, sends `Event::ProgramsChanged`; `print_config`.
- `main.rs`: binary entry; `kotodamad [--config <dir>]` calls `start`, `kotodamad [--config <dir>] config [--schema]` calls `print_config`.
- `daemon.rs`: the state machine. `Daemon::handle(Event)` is the one entry point; `Event`, `Output`, `Launcher`/`Desktop` traits, the types below. Its methods are in sibling `impl Daemon` blocks under `daemon/`, by concern: `extensions.rs` (each Extension's run, restarts, `set_extensions`), `from_extension.rs` (what an Extension sends: Items, Views, Live results, `action_done`), `front_ends.rs` (sessions, Front end messages, requests for a menu, output), `openings.rs` (`open --view`), `picks.rs` (running Actions, picks, forgetting), `undo.rs`, `settings.rs` (a config load and the problems), `search.rs` (`flush`, `refresh` and the sources it ranks), `empty.rs` (the Empty query), `rows.rs` (sources to rows, the catalog), `hot.rs` (hot Items and pins). `Daemon::run_catalog_action` runs a confirmed Proposal (ADR 0019); when several Items offer it, `Daemon::offer_pick` lists them in a View of its own (`Daemon::picks`, `pick_lists`), `run_pick` runs the one picked, and `cancel_pick` (Esc, a new query, the Extension stopping) runs nothing (ADR 0022).
  - `Candidate`, `Candidate::score` (its points, `points.rs`), `Candidate::rank_key` (one `u64` per Candidate, set once by `key_candidates`, its bit fields in `key_bits`) and `Candidate::rank`: the full Result order (`Standing`: answers first, fallbacks last, ADR 0016; then `Class`: an Alias, exact matches and the Learned choice; then the points; then an exact title over an exact keyword, then kind order; ADR 0032, 0021). `Daemon::add_points` (`daemon/search.rs`) scores the candidates once their Frecency and what the query names are known. `Own::tier_cap`: an app's entry Item matches at most as a word start (ADR 0027).
  - Aliases: `Daemon::alias_source`, `Source::Unavailable` and `Daemon::unavailable_row` (an Alias whose Item is gone or whose Extension is down: a row that can't run, the Item as `last_seen` before its Extension stopped); `row` badges a Result the Alias named.
  - Requests for a menu (ADR 0029): `Daemon::menu` (the one menu `kotodama open` and `toggle` go to: of the Front ends that never asked for one, `Session::asked_for_menu`, the one shown last, `shown_last`, else the newest), `Daemon::ask_menu` (passes it on and answers `ToFrontEnd::Reached`), `to_menu`, and `awaiting_menu` with `settle_awaiting_menu` (with no menu, waits `MENU_WAIT` for one to search, then answers that it reached none).
  - `Session`: per-Front-end state (query, shown Results, list View filters). Late Results rerank the rows while `Session::reranks` (until `FromFrontEnd::SelectionMoved` or `RERANK_FOR` after the keystroke), then go below the rows `FromFrontEnd::Viewport` names (ADR 0020). `Session::send_results` numbers each `Results` and notes, in `Session::risen`, the version a late update last added or moved up each Result; `Daemon::unseen` refuses a `RunAction` whose `shown` version predates it.
  - Views: `Daemon::filter_view` and `send_filtered` (a list View's filter, or `ToExtension::FilterView` when it filters itself), `view_contributed` (Contributed actions by Item kind), `front_end_up` re-sends the open Views to a Front end that connects. Hidden Items (ADR 0015) live in `Daemon::hidden`, outside the Index, for `--view` alone.
  - `Daemon::query`, `Daemon::empty_query`: searching, and what shows before typing. `Daemon::shown` (`FromFrontEnd::Shown`) ranks a session's Empty query again when `history::part_of_day` changed since `Session::empty_ranked_in`. `Daemon::refresh` narrows a search to the last one's matches (`LastSearch`: a `Narrowing` of slots at one Index version, and the near misses; forgotten on the Empty query); `Daemon::add_near_misses` adds Near misses when real matches leave rows empty (ADR 0013); `Daemon::add_fallbacks` adds a Fallback's Live results (`[live_query] fallback`), last, after `learn`, and asks it the query, under the same condition (ADR 0016). `Daemon::picked` never makes a Fallback's Result a Learned choice, nor anything picked in an app kept out of the search (`Session::in_private_app`: its `searched` all false, as the clipboard's and the emoji's), whose queries may be private and stay out of the Usage log too (`Daemon::query` logs none of them, a pick there is logged without its query), and keeps nothing of an answer (`Session::is_answer`) but its Usage log entry.
  - Own Results under `OWN = "kotodama"` (ADR 0005): `FORGET` (bound to `FORGET_SHORTCUT` in `offer_forgetting`), `CLEAR_HISTORY`, `UNDO` (ADR 0010). Undo: `Daemon::changed` keeps an `Undoable` for `[history] undo_seconds` (`UNDO_FOR` by default) and broadcasts `OfferUndo` (its `Done` words); `Daemon::undo` (the Undo Result, or `FromFrontEnd::Undo`) and `expire_undos` send `WithdrawUndo`; `front_end_up` offers the latest. A run of an Extension's Action keeps its pick as an `Undoable` too, by the invocation, `UndoneBy::Extension`, never offered: `Daemon::withdraw_pick` (`FromExtension::WithdrawPick`) undoes it, and `History::undo` takes that one pick off an entry changed since (`Picks::take_off`, `Learned::withdraw`, which brings back the choice the pick replaced). Limits `MAX_RESULTS`, `MAX_LIVE_RESULTS`.
  - Hot Items (ADR 0017, 0023): `Daemon::plan_hot` (the Empty query's Items, then Learned choices (`Daemon::cache_learned`) and the time-of-day habit around now, within `HOT_CAPACITY`, re-planned every `HOT_EVERY` and `HOT_SETTLE` after a change; the plan also ranks the Empty query ahead, kept as `Daemon::ahead`, and `Daemon::most_used` ranks inline, counted by `Daemon::ranked_here`, only when no ranking made ahead stands), the menu opening (`open`, `toggle`) or showing (`FromFrontEnd::Shown`) warms the CPU cache (`Index::warm`, counted by `Daemon::warmed`); `next_wake` is `next_deadline` plus the hot timer.
- `rank.rs`: match quality. `Tier` (`Tier::Keyword` the Item's own keyword exactly, while one of its `keywords` exactly is a word start, ADR 0034; `Tier::WeakKeyword`, the query inside a weak keyword, ADR 0035; `past_symbols`: a title past the symbols that lead it, as `🔥 Fire`, ADR 0021), `Query` (folding, `searches_subtitles`), `Letters` (character sets as bits; `meet_block`), `Filter` (what lets a search skip Items before nucleo; `may_match_block` tests `BLOCK` rows in one vectorised loop), `Searched` (the texts scored before a match), `Haystack`, `fold_text`, `Folded` (what a Segment keeps of an Item's texts; ASCII texts are folded and split into words in vectorised byte loops, `byte_mask`). `Tiers::near_miss`, `Tiers::near_miss_highlights` and `LETTERS_PER_TYPO`: typo tolerance (ADR 0013). `OPTIMAL_CHARS`: longer texts are scored by nucleo's greedy match (ADR 0017).
- `points.rs`: a Result's points, how well it matches and its habit blended (ADR 0032): `TIER`, `habit` (the curve from Frecency), `points` (with an Extension's boost, squeezed below each band's ceiling so the most used keep their order, held to the bounds: near misses below real matches, the exact band reached only by an exact match or a word start used enough, a weak keyword never reaching a word start), `band`.
- `narrowing.rs`: `Narrowing`, the one set of rules for when a query only adds to the last one and need search only its matches; the search (`Daemon::refresh`) and a list View's filter (`Views::filter`) both use it. It keeps every match the matcher scored, Tier or not.
- `index.rs`: `Index`, every Indexed item: two `Segment`s per Extension (`SIDES`, `segments_of`: the Items the search shows, then those its app alone shows), searched with nucleo (`search` hands each match's `Ranked` row to its caller, `starting_with`); `Slot` (Segment and row), `SlotHasher`; `split` (an Extension's change as an edit to each of its Segments, by `app_only`); `Reach` (the whole search, which reads the Segments `set_searched` leaves searched, or one app's two), `first` (an Extension's rows in order); `keyed` (keywords), `identified` (shared identities, ADR 0008). `Index::item` reads an Item back off its Shelf (counted by `shelf_reads`) and keeps it resident (`SHOWN_RESIDENT` read last, plus the hot ones and those a keyword or an Alias names: `set_hot`, `hot_read`, `pin`, `trim`); `keep` takes `Read`s made on the indexing thread; `ItemRef` is a resident or borrowed Item.
- `segment.rs`: `Segment`, one Extension's Items laid out for scanning (ADR 0017): dense `Letters` arrays, one text arena, word starts (`Keys`, 56 bytes; weak keywords after the keywords text, behind `WEAK_AT`, ADR 0035); `Segment::rows_where` tests the dense arrays a block at a time and hands on the rows whose bits are set; `Segment::score` reads a row's title and keywords, the rest only on a match; `Ranked` (a row's keys for ranking, its texts on demand); `Held` (id, Identity, keyword, Actions on offer, `Place` on the Shelf); `Edit`; rows emptied in one version are reused from the next (`next_version`).
- `indexer.rs`: `Indexer`, the `index` thread that makes Extensions' changes into new Segment versions off the keystroke path, coalescing what queues up; the Daemon swaps them in on `Event::Indexed`, both of an Extension's Segments at once. The thread also plans the hot Items and ranks the Empty query ahead (`Plan`, `LEARNED_SHARE`) and reads them and the keyword and Alias targets off their Shelves, sent with each version or as `Event::Kept`.
- `payload.rs`: `Shelf`, the append-only store of encoded Items (an unlinked file in `$XDG_CACHE_HOME/kotodama`, or memory); `Place`.
- `reserved.rs`: drops Reserved keys from Extensions' Actions as they arrive and keeps the Actions: `release_message` (Items, Live results, list Views; called first in `Daemon::extension_message`, which sends a `ToExtension::Rejected` for each `Released`), `in_manifest` (Contributed actions bound to one, a problem of the Manifest in `discovery.rs:load` and `configured.rs:configure`; `extensions_changed` drops the binding).
- `history.rs`: `History` on disk (`$XDG_STATE_HOME/kotodama/history.json`, scores as `f32`); `Picks` (a Result's decayed picks and their shares of the parts of the day, kept twice, for weekdays and for weekends; `Kept` loads a file from before the kinds of day), `Picks::frecency`, `Picks::habit`, `Frecent` (picks as a struct of arrays, decayed in one vectorised loop for the empty query and a search's Frecency), `part_of_day` (the part of the day a time falls in), `next_part` (when the next one starts), `weekend` (how much of a weekend a moment is, fading across midnight), `History::learned` (Learned choices), `History::choices` (every Learned choice and its strength), `Settings::from_config` (with `time_of_day`, `day_of_week`, `undo_seconds`, `max_results` and `max_queries`).
- `clock.rs`: `Clock`, `When` (time of day and day of the week for Frecency, ADR 0009 and 0033; `When::local`, `When::utc`, `When::plus`); the time zone is read again (`tzset`) once a wall-clock minute, `ZONE_SECS`.
- `kind_order.rs`: `KindOrder::place`, configurable kind order for equal matches (shared kinds by `ItemKind::shared_index`); `KindPlaces`, the place of each Segment's kinds, worked out per search.
- `empty_query.rs`: `EmptyQuery::from_config`, the Empty query and its Fixed menu (`None` when unset: `Daemon::empty_query` then lists the apps' entry Items).
- `most_used.rs`: the Empty query's most used Results: `Picked` (the picked Indexed items, shared with the indexing thread), `Usage::rank`, and `Ahead` (the rankings made ahead and when one stands, ADR 0023).
- `keywords.rs`: Aliases and Quicklinks from config (`Keywords`, `Quicklink::command`), `Keywords::holder` and `Keywords::conflicts`; URL templates and the opener are `kotodama_extension::url`.
- `conflict.rs`: the keyword table's precedence (ADR 0028): `Holder`, `Conflict` (a keyword lost, and what the loser got), `report`, the one place conflicts reach the user (as problems, `problem::Report`). `Daemon::load_apps` reports them when they change.
- `problem.rs`: what is wrong that the user can fix. `Report` (each setting's reader adds to it, by dotted key, and it logs each), `Problems` (the Daemon's, by where they were found: `unreadable` config, `config`, `manifests`, `extensions` (from `[extensions.<name>]`), `apps`, `conflicts`; `list` adds those of Extensions that are down, `Extension::problem`), `item` and `view` (the own Item `problems`, shown while there are any, and the Detail View it opens, kept up to date in `Daemon::problems_open`). The Daemon side: `Daemon::update_problems` (in `flush` when `Problems::dirty`, and in `front_end_up` so the first `Status` is current; sends `ToFrontEnd::Status` with `down`), `config_failed` (`Event::ConfigFailed`). An Extension whose run `Ended::CantStart` or was `Ended::Refused` goes `State::Failed` and isn't restarted until its Manifest changes (`set_extensions`) or its program's `discovery::Stamp` does (`programs_changed`). `../tests/problems.rs`.
- `open_view.rs`: `kotodama open --view` (ADR 0014): `ViewName` (`<extension>/<item>`), `Opening`. The Daemon side is `daemon/openings.rs:Daemon::open_on_view` (runs the Item's primary Action, holds `Open`/`Toggle` back until the View is there, `OPEN_VIEW_TIMEOUT`).
- `views.rs`: `Views`, every View Extensions have open, the top last; `Views::filter` matches a list View's Items with the search's matcher and Tiers, narrowing as the user types on (a `Narrowing` of positions in the list), highlights for the first `HIGHLIGHTED`.
- `apps.rs`: `Apps`, every Extension's app (ADR 0027): its word from `[extensions.<name>] word` (or `prefix`, its old name), the Manifest's `word` or the name, given out by `Apps::new` in the precedence of `conflict.rs`, which of its Segments the search reads (`in_search`) and its `boost` (`Apps::boosts`, kept by Extension in `Daemon::boosts` and read by `Daemon::add_points`); `Apps::scope_of` (the app a query starts with the word of), `Apps::searched`; `App::entry`, the entry Item, an own Result `app:<extension>` of kind `kotodama.app`; `App::scope`, with the intro card while nothing is typed and the Extension's note on it. An entry Item shows only while its Extension can do anything (`Extension::usable`: its last `Status`, else once its Items are in or it has Live queries); `Daemon::said` rebuilds the own Items when that changes, never per keystroke, and works out `Extension::asked`, the debounce of the Live queries it is sent, `None` while it said it can't do anything (`ask_typed` sends what is typed once it can again). The Daemon side: `Session::entered` (the app entered, by its entry Item or `Open`), `Session::reach`, `live_query` and `asks` (Live queries in an app), `read_query`, `Daemon::load_apps` (sets `Index::set_searched`), `Daemon::empty_app` (commands, most used, then the rest), `OwnAction::App` (sends `ToFrontEnd::SetQuery` with what followed the word, `Daemon::after_word`, which `row` shows as `Search <app> for “…”`). `../tests/apps.rs` enters apps on a desk with emoji, windows and binds.
- `pick.rs`: `Pick`, a confirmed Proposal waiting for the user to pick its Item; `view`, the list that asks, each Item with the one Action `PICK`.
- `arguments.rs`: text after a keyword filling an Action's Arguments, and the form for missing ones (a file field for a file or folder Argument); `absolute`, a file or folder Argument (`absolute_paths`, in `Daemon::run_action`) or an Extension form's file field (`absolute_fields`, on `SubmitForm`) made an absolute path from `Daemon::home`.
- `completion.rs`: completing a form's file field (`FromFrontEnd::CompletePath`, answered with `ToFrontEnd::PathCompletions`): `Completer` (directory listings kept, `CACHED_DIRS` of them, each checked again with one `stat` and capped at `MAX_LISTED` entries; a partial path ranked by `rank.rs`'s Tiers, folders before files within a tier; a directory's stamp under `COARSEST_STAMP` old is read again; with nothing typed the newest files from `recent_dirs`), `Completions` (the `completion` thread, `Daemon::complete_in_background`, answering with `Event::Completed`; inline in tests), `Settings` (`[files] recent_dirs`; `user_dirs`, the XDG user directories from `user-dirs.dirs`); `completion/accept.rs`: `Accept`, the files a field takes, by extension or by MIME type through the shared MIME-info database's `globs2`. The Daemon side: `Daemon::complete_path` (`daemon/front_ends.rs`, the field looked up in an argument form, `ArgumentForm::fields`, or an Extension's form View). ADR 0036.
- `config.rs`: `load` (merge every `*.toml` in config dirs; `Error` names the file), `parse` (`ParseError`), `load_with_sources` (and the file each key came from, `Sources`), `watch` (a `kotodama_extension::watch::Watcher` on thread `config`, on the config dirs and the directories a symlinked config file leads through, read again on each reload), `extension_table` (`[extensions.<name>]`), `extension_settings` (the table as the Extension gets it, without `DAEMON_KEYS`, and without `MANIFEST_KEYS` for an Extension defined in the config), `to_toml`.
- `engine.rs`: `Engine::from_config`, the settings of `[search]` (`rows`, `near_misses`, `fallbacks`), the restart policy in `[extensions]` (`retry_max`, `give_up_after`), `[desktop]` (`DesktopSettings`, `Paste`) and `[log]`; `check_tables` reports a top-level table that isn't one (`TABLES`); `log_from_env`. The Daemon side: `Daemon::load_engine`, `extension_down` (the backoff cap, giving up).
- `configured.rs`: `configure`, the installed Extensions as `[extensions.<name>]` changes them: `enable = false` leaves one out, `command`, `env` and `live_query` override the Manifest's, and a table with a `command` and no installed Extension of its name defines one (`Found::inline`). The Daemon side: `Daemon::configure_extensions`, on `Event::Extensions` and every config load. `../tests/engine.rs`.
- `schema.rs`: `KEYS`, every config key with its default and doc, and whether it is read only at start; `print_schema` (`kotodama config --schema`), `print_config` (`kotodama config`: the merged config with defaults and each value's source file).
- `discovery.rs`: `discover` (`<dir>/*/manifest.toml`; `Discovered`, the Extensions and the problems of the Manifests refused), `watch` for Extension dirs (a `Watcher` on thread `extensions`); `Found` (with the `env` and `inline` the config gives), `Found::new` (refuses a Manifest with `Error`), `Found::stamp` (`Stamp`, to tell a program changed), `program` (a bare name from the config, `command_from_config`, is looked up on PATH; a Manifest's never is).
- `host.rs`: `Processes`, spawning Extension processes with reader/writer threads; tells how each run ended (`daemon::Ended`: stopped, can't start, refused at the handshake).
- `link.rs:pump`: post-handshake connection threads (Extension or Front end); for an Extension, a message that doesn't decode is answered with `ToExtension::Rejected` and its reason, as `daemon/from_extension.rs:extension_message` does for one it may not send.
- `server.rs`: `listen`, `serve`, the Front end Unix socket.
- `desktop.rs`: paste/type worker over Wayland (virtual keyboard, `Keymap`, `Wayland`, `Worker`); `launch` starts a Quicklink's command through `kotodama_extension::launch::launch` on a thread of its own (a scope of its own, `WAYLAND_DISPLAY` passed on, as `host.rs` passes it to Extensions); data-control and finding the compositor are `kotodama_extension::wayland`; keys wait `[desktop] settle_ms` after the menu closes (`settle_left`), and a paste is Ctrl+V, Ctrl+Shift+V or typed, as `[desktop] paste` says (`Wayland::configure`).
- `notify.rs:send`: desktop notifications over D-Bus (`kotodama_extension::dbus`).
- `paths.rs`: `config_dirs` (`--config`, `KOTODAMA_CONFIG_DIR`, else XDG; `Error` when a path has no place), `Overrides::from_config` (`[paths]`), `Paths::new` (socket, state and cache dirs: `[paths]` over XDG, `KOTODAMA_SOCKET` over both; ADR 0030), `extension_dirs`.
- `usage.rs`: opt-in Usage log (`Writer`, `forget`).
- `../benches/`: `query.rs` (criterion: keystrokes, empty query, batches, cold cache, long titles), `instructions.rs` (gungraun: instructions per keystroke, with the emoji in the Index in the whole search, left to their app and searched in it, and for the empty query with 2,000 Results picked, compared against the base commit in CI), `daemon.rs` (the real Daemon: socket p99 and resident memory with 10k Items), `memory.rs` (heap per Indexed item), `completion.rs` (criterion: a keystroke in a file field on a directory of 1,000 entries, listing it all, and the first keystroke, which reads it); `support/setup.rs` is the Daemon `query.rs` and `instructions.rs` both drive, on a clock that stands still at `setup::START` so counts repeat exactly, `support/corpus.rs` the Items.
- `../tests/`: `support/harness.rs` is the harness most of them drive the Daemon through (Extensions and Front ends as channels, launches and typing recorded), each including it with `#[path]`; `fixtures/recorder` an Extension that records what it is sent.
