# kotodamad code map

The Daemon. Maintained by hand: fix stale lines when you find them, and update this map in the PR that adds, moves or renames a module here. Paths are relative to `src/`; tests are in `tests/`, benches in `benches/`. See also the [root map](../../CODEMAP.md) and [GLOSSARY.md](../../GLOSSARY.md).

- `lib.rs:run`: wires paths, config, discovery, watchers, server and the main loop.
- `main.rs`: binary entry; calls `run`.
- `daemon.rs`: the state machine. `Daemon::handle(Event)` is the one entry point; `Event`, `Output`, `Launcher`/`Desktop` traits. `Daemon::run_catalog_action` runs a confirmed Proposal (ADR 0019).
  - `Candidate` and `Candidate::rank`: the full Result order (`Standing`: answers first, fallbacks last, ADR 0016; then Tier, then Learned choices/Frecency, then kind order; ADR 0006, 0011).
  - Aliases: `Daemon::alias_source`, `Source::Unavailable` and `Daemon::unavailable_row` (an Alias whose Item is gone or whose Extension is down: a row that can't run, the Item as `last_seen` before its Extension stopped); `row` badges a Result the Alias named.
  - `Session`: per-Front-end state (query, shown Results, list View filters). Late Results rerank the rows while `Session::reranks` (until `FromFrontEnd::SelectionMoved` or `RERANK_FOR` after the keystroke), then go below the rows `FromFrontEnd::Viewport` names (ADR 0020). `Session::send_results` numbers each `Results` and notes, in `Session::risen`, the version a late update last added or moved up each Result; `Daemon::unseen` refuses a `RunAction` whose `shown` version predates it.
  - Views: `Daemon::filter_view` and `send_filtered` (a list View's filter, or `ToExtension::FilterView` when it filters itself), `view_contributed` (Contributed actions by Item kind), `front_end_up` re-sends the open Views to a Front end that connects. Hidden Items (ADR 0015) live in `Daemon::hidden`, outside the Index, for `--view` alone.
  - `Daemon::query`, `Daemon::empty_query`: searching, and what shows before typing. `Daemon::shown` (`FromFrontEnd::Shown`) ranks a session's Empty query again when `history::part_of_day` changed since `Session::empty_ranked_in`. `Daemon::refresh` narrows a search to the last one's matches (`Narrowing`, forgotten on the Empty query); `Daemon::add_near_misses` adds Near misses when real matches leave rows empty (ADR 0013); `Daemon::add_fallbacks` adds a Fallback's Live results (`[live_query] fallback`), last, after `learn`, and asks it the query, under the same condition (ADR 0016). `Daemon::picked` never makes a Fallback's Result a Learned choice, and keeps nothing of an answer (`Session::is_answer`) but its Usage log entry.
  - Own Results under `OWN = "kotodama"` (ADR 0005): `FORGET` (bound to `FORGET_SHORTCUT` in `offer_forgetting`), `CLEAR_HISTORY`, `UNDO` (ADR 0010). Undo: `Daemon::changed` keeps an `Undoable` for `UNDO_FOR` and broadcasts `OfferUndo` (its `Done` words); `Daemon::undo` (the Undo Result, or `FromFrontEnd::Undo`) and `expire_undos` send `WithdrawUndo`; `front_end_up` offers the latest. A run of an Extension's Action keeps its pick as an `Undoable` too, by the invocation, `UndoneBy::Extension`, never offered: `Daemon::withdraw_pick` (`FromExtension::WithdrawPick`) undoes it, and `History::undo` takes that one pick off an entry changed since (`Picks::take_off`). Limits `MAX_RESULTS`, `MAX_LIVE_RESULTS`.
  - Hot Items (ADR 0017): `Daemon::plan_hot` (time-of-day habit around now, `HOT_CAPACITY`, `HOT_LEAD_SECS`/`HOT_GRACE_SECS`, re-planned every `HOT_EVERY` and `HOT_SETTLE` after a change), the menu opening warms the CPU cache (`Index::warm`); `next_wake` is `next_deadline` plus the hot timer.
- `rank.rs`: match quality. `Tier`, `Query` (folding, `searches_subtitles`), `Letters` (character sets as bits; `meet_block`), `Filter` (what lets a search skip Items before nucleo; `may_match_block` tests `BLOCK` rows in one vectorised loop), `Searched` (the texts scored before a match), `Haystack`, `fold_text`, `Folded` (what a Segment keeps of an Item's texts; ASCII texts are folded and split into words in vectorised byte loops, `byte_mask`). `Tiers::near_miss`, `Tiers::near_miss_highlights` and `LETTERS_PER_TYPO`: typo tolerance (ADR 0013). `OPTIMAL_CHARS`: longer texts are scored by nucleo's greedy match (ADR 0017).
- `index.rs`: `Index`, every Indexed item: one `Segment` per Extension, searched with nucleo (`search` hands each match's `Ranked` row to its caller, `starting_with`); `Slot` (Segment and row), `SlotHasher`; `keyed` (keywords), `identified` (shared identities, ADR 0008). `Index::item` reads an Item back off its Shelf and keeps it resident (`SHOWN_RESIDENT` read last, plus the hot ones and those a keyword or an Alias names: `set_hot`, `hot_read`, `pin`, `trim`); `keep` takes `Read`s made on the indexing thread; `ItemRef` is a resident or borrowed Item.
- `segment.rs`: `Segment`, one Extension's Items laid out for scanning (ADR 0017): dense `Letters` arrays, one text arena, word starts; `Segment::rows_where` tests the dense arrays a block at a time and hands on the rows whose bits are set; `Segment::score` reads a row's title and keywords, the rest only on a match; `Ranked` (a row's keys for ranking, its texts on demand); `Held` (id, Identity, keyword, Actions on offer, `Place` on the Shelf); `Edit`; rows emptied in one version are reused from the next (`next_version`).
- `indexer.rs`: `Indexer`, the `index` thread that makes Extensions' changes into new Segment versions off the keystroke path, coalescing what queues up; the Daemon swaps them in on `Event::Indexed`. The thread also plans the hot Items (`Plan`) and reads them and the keyword and Alias targets off their Shelves, sent with each version or as `Event::Kept`.
- `payload.rs`: `Shelf`, the append-only store of encoded Items (an unlinked file in `$XDG_CACHE_HOME/kotodama`, or memory); `Place`.
- `reserved.rs`: drops Reserved keys from Extensions' Actions as they arrive: `release_message` (Items, Live results, list Views; called first in `Daemon::extension_message`), `release_actions` (Contributed actions, in `extensions_changed`).
- `history.rs`: `History` on disk (`$XDG_STATE_HOME/kotodama/history.json`, scores as `f32`); `Habit::frecency`, `Frecent` (picks as a struct of arrays, decayed in one vectorised loop for the empty query and a search's Frecency), `part_of_day` (the part of the day a time falls in), `History::learned` (Learned choices), `Settings::from_config`.
- `clock.rs`: `Clock`, `When` (time of day for Frecency, ADR 0009); the time zone is read again (`tzset`) once a wall-clock minute, `ZONE_SECS`.
- `kind_order.rs`: `KindOrder::place`, configurable kind order for equal matches (shared kinds by `ItemKind::shared_index`); `KindPlaces`, the place of each Segment's kinds, worked out per search.
- `empty_query.rs`: `EmptyQuery::from_config`, the Empty query and its Fixed menu.
- `keywords.rs`: Aliases and Quicklinks from config (`Keywords`, `Quicklink::command`); URL templates and the opener are `kotodama_extension::url`.
- `open_view.rs`: `kotodama open --view` (ADR 0014): `ViewName` (`<extension>/<item>`), `Opening`. The Daemon side is `daemon.rs:Daemon::open_on_view` (runs the Item's primary Action, holds `Open`/`Toggle` back until the View is there, `OPEN_VIEW_TIMEOUT`).
- `views.rs`: `Views`, every View Extensions have open, the top last; `Views::filter` matches a list View's Items with the search's matcher and Tiers, narrowing as the user types on (`Narrowing`), highlights for the first `HIGHLIGHTED`.
- `arguments.rs`: text after a keyword filling an Action's Arguments, and the form for missing ones.
- `config.rs`: `load` (merge every `*.toml` in config dirs), `watch` (a `kotodama_extension::watch::Watcher` on thread `config`), `extension_table` (`[extensions.<name>]`).
- `discovery.rs`: `discover` (`<dir>/*/manifest.toml`), `watch` for Extension dirs (a `Watcher` on thread `extensions`); `Found`.
- `host.rs`: `Processes`, spawning Extension processes with reader/writer threads.
- `link.rs:pump`: post-handshake connection threads (Extension or Front end).
- `server.rs`: `listen`, `serve`, the Front end Unix socket.
- `desktop.rs`: paste/type worker over Wayland (virtual keyboard, `Keymap`, `Wayland`, `Worker`); `launch` and `host.rs` pass `WAYLAND_DISPLAY` on; data-control and finding the compositor are `kotodama_extension::wayland`; keys wait `SETTLE` after the menu closes (`settle_left`).
- `notify.rs:send`: desktop notifications over D-Bus (`kotodama_extension::dbus`).
- `paths.rs:Paths::from_env`: socket, config, state, cache and Extension dirs from XDG.
- `usage.rs`: opt-in Usage log (`Writer`, `forget`).
- `../benches/`: `query.rs` (criterion: keystrokes, empty query, batches, cold cache, long titles), `instructions.rs` (gungraun: instructions per keystroke and for the empty query with 2,000 Results picked, compared against the base commit in CI), `daemon.rs` (the real Daemon: socket p99 and resident memory with 10k Items), `memory.rs` (heap per Indexed item); `setup/` is the Daemon `query.rs` and `instructions.rs` both drive, `corpus/` the Items.
