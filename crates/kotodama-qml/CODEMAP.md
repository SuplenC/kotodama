# kotodama-qml code map

The Quickshell Front end. Maintained by hand: fix stale lines when you find them, and update this map in the PR that adds, moves or renames a module here. See also the [root map](../../CODEMAP.md) and [GLOSSARY.md](../../GLOSSARY.md).

- `qml/KotodamaMenu.qml`: the menu UI; theme properties at the top (colors, font, sizes, `maxRows`, `showHints`); `hints`, the footer's key hints for the selected row (`KotodamaSearch.hints`, `Row::hints`) when it has no failure to show. the app chip (`chip`) sits before the search box and the intro card (`intro`) over the list; Tab on an entry Item enters its app; Esc clears the text, else pops the View, else leaves the app, else closes the menu (in `key`); while an Action that asks first waits, the footer shows `KotodamaSearch.confirming`, Enter runs it (`confirm`) and any other key drops it (`cancelConfirm`), Esc doing nothing else; Backspace on the empty box calls `leaveScope`; `key(event)` is every View's keys (the Toast's undo key first; `ctrlOnly` for the menu's own Ctrl keys); the Toast sits under the footer, and the footer's right end counts the Daemon's problems (`KotodamaSearch.problems`), which a click lists (`showProblems`). A row draws an Alias badge and greys out when unavailable; when a verb in the query chose the Action Enter runs (`primaryChosen`), a pill after the badge names it in its role's colour (`roleText`, `roleBorder`), as does the footer's `↵` hint (`chosenHints`); a `form` Action's title ends in "…" (`actionTitle`). The Action panel puts a line between the Item's own Actions, the Contributed ones and the destructive ones, drawn red (`panelSection`). The pointer selects a row only when it moves (`list.hover`).
- `shell/shell.qml`: the ready Front end, the menu alone as a Quickshell config; the Nix package installs it in `share/kotodama/quickshell`, and home-manager's `frontEnd.look` writes a copy with properties set.
- `src/bridge.rs`: the cxx-qt bridge, `KotodamaSearch` as QML sees it: every property, invokable and signal, with its doc; `build.rs` generates the C++ from this file.
- `src/lib.rs`: `SearchRust`, the state behind `KotodamaSearch`, and what QML's calls do. In an app: `scope` (the chip's title), `word`, `sent` (the query last sent, the word and all), `enter_scope` (on `Results` with a `Scope`), `leaveScope` (Backspace), `drop_scope` (on `Open`, `Toggle` and `SetQuery`), `queryReplaced` (the box shows the rest). The Toast: `toast` (what it says), `offered` (the change it undoes), `undo`, `isUndoKey` (`UNDO_SHORTCUT`), `set_toast`. `shown` sends `FromFrontEnd::Shown` whenever `KotodamaMenu.qml` becomes visible. `select` tells the model which row is selected, and sends `SelectionMoved` once per query. `run_action` holds an Action that asks first (`Row::confirmation`) in `unconfirmed` until `confirm`; `cancel_confirm` drops it, as typing, a new selection and a View opening or closing do. `frameStarted` (on `afterAnimating`) and `painted` (on `frameSwapped`) record the Results version on screen, which `run_action` confirms as `shown`. `enter(row)` enters an entry Item's app (`Row::enters`), `leaveApp()` goes back to the whole search; `introAbout`, `introExamples` (`variant::examples`) and `introNote` (what the Extension said, such as why it can't do anything) hold the intro card. `problems` counts the problems `Status` lists; `showProblems` runs `Problem::list`.
- `src/updates.rs`: what the Daemon's messages do, on the Qt thread: `apply` takes a batch, one `apply_one` per `connection::Update`, and shows what it adds up to once (`views::Shown`). `show_rows` puts a list View's Items in place of the Results (kept in `results`) and diffs them, emitting `selectRow` so its selected Item stays selected.
- `src/model.rs`: the list model: the roles (`MARKUP`, `PRIMARY_ROLE`, the role of the Action Enter runs, as `primaryRole`, `PRIMARY_TITLE` its title, as `primaryTitle`, `PRIMARY_CHOSEN`, whether the query chose it by a verb, as `primaryChosen`, and the rest), `data`, `roleNames`, `rowCount`, and `QtModel`, `rows::Model` over Qt's begin/end signals.
- `src/scope.rs`: `behind` (what a query has after an app's word) and `full` (the query sent for the box in one). Unit tests in `src/scope/tests.rs`.
- `src/connection.rs`: the Daemon connection thread (`spawn`, `Update`, `Writer`); `update` skips `Reached`, the answer to a request for a menu, which a menu never makes; messages that arrived together reach the Qt thread in one batch, shown once (`updates.rs:apply`); `ConnectError` for a failed connect.
- `src/rows.rs`: `Row` (`Row::listed` for a list View's Items, `Row::relist` to update one in place, `Row::hints` for the footer, `Row::confirmation` for what it asks before an Action that asks first), `Rows` (the model's rows, a gap buffer), `Model`; `replace` (by position, for the Results) and `diff` (by Item key, for list Views: removes, moves, inserts and changes only what differs; `Fresh` gives it the new rows), Action panel entries (`Row::actions`: the primary, which is the Action the query chose (`Chosen`, from `ShownResult::primary`) or else the first own one, the other own Actions, the Contributed ones, then every destructive one but the primary; `Row::primary_title`, `Row::primary_chosen`; `Row::action` runs the entry at the same place, `Row::place_of` finds where the open panel's entry is since, for `runListed`; `PanelEntry::shortcut` drops a contributed shortcut an own Action binds; `Row::primary_role`). Unit tests in `src/rows/tests.rs`.
- `src/views.rs`: `Views` stack, form values (a number field's typed text kept as a number when it is one; `Views::toggle_option` for a multi-select), the Daemon's errors per field (`Views::set_errors`, `Views::errors`, cleared by `submit`), jobs; the file field being completed (`Views::complete`, `Views::completed`, which keeps only the answer to what was typed last, `Views::completions`); a list View's filter, the Daemon's matches (`Views::set_filter`, `Views::filtered`, `Open::listed` making rows only as `rows::diff` needs them) and Contributed actions by kind. Unit tests in `src/views/tests.rs`.
- `src/variant.rs`: Views (a form field's `kind`: `text`, `textarea`, `checkbox`, `select`, `multiselect`, `file`, `folder`, `number`, `date` or `description`, with `optional` and `pattern`), `field_errors` (`KotodamaSearch.fieldErrors`), jobs and actions as QVariant maps for QML (`actions`: each panel entry's title, group, shortcut, `role` and `keywords`), and `completions`, the paths offered for a file field (`KotodamaSearch.completions`, `completingField`, asked for by `complete`).
- `src/shortcut.rs:matches`: Action key bindings like `ctrl+o`. Unit tests in `src/shortcut/tests.rs`.
- `src/plugin.rs`: Qt plugin entry symbols. `build.rs`: cxx-qt build, from `src/bridge.rs`.
- `benches/filter.rs`: a filter reply on a 1000-Item list View, Qt-free (it compiles `rows.rs` and `views.rs` itself, since the cdylib can't be linked).
