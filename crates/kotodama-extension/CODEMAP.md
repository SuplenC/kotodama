# kotodama-extension code map

The runtime every Rust Extension is built on: the Bundled extensions, and any installed separately. The Daemon uses its watcher. Maintained by hand: fix stale lines when you find them, and update this map in the PR that adds, moves or renames a module here. Paths are relative to `src/`. See also the [root map](../../CODEMAP.md) and [GLOSSARY.md](../../GLOSSARY.md).

- `lib.rs`: `main` (lean memory, log name, exit code), `connect` (handshake and the `read` thread, which logs the reason of a `rejected`) returning `Connection`; `Event<T>`, `Writer`, `lean_memory`, `log!` (a warning: to the `log` logger if one is installed, as in the Daemon, else stderr), `Chain` (an error and its causes for a log line), `STACK_SIZE`. The crate docs hold a whole example Extension.
- `items.rs`: `SentItems::publish` (send only the Items added, changed or gone).
- `status.rs`: `SentStatus` (`usable`, `noted`, `unusable`: tell the Daemon whether the Extension can do anything at the moment, and the note for its app's intro card, each change once).
- `config.rs`: `command`, `string`, `boolean`, `strings`, `warn` for an Extension's config table.
- `dirs.rs`: `state`, `cache` (XDG directories for an Extension).
- `url.rs`: `fill` (a `{query}` template, percent-encoded), `opener` (`xdg-open`), `percent_encode`; shared by the Daemon's Quicklinks and web search.
- `launch.rs`: the one launch path, the Daemon's included. `launch` (detached), `launch_watched` (for an `App`, whose desktop id names the scope; also hears when everything the launch started closed soon, unless a copy of the app ran before: `closing.rs`), `background` (reports `Ended` with the last output line); both pass `WAYLAND_DISPLAY` on (`runtime::pass_wayland_display`), and start each program in a scope (`scope::spawn`).
- `closing.rs`: `ended_by` (the scope's cgroup empty, else the process group gone, by a deadline), `ran_before` (a same-user process of the program, by argv0 or executable name, started before the launch; scans `/proc`).
- `scope.rs`: `spawn` (returns `Launched`, the child and its scope's cgroup; a program in a systemd scope of its own from the user manager, moved in before it runs: the child waits in `pre_exec` for the `scope` thread's D-Bus call; skipped for a launch prefix or no user manager; the program never inherits `KOTODAMA_LAUNCH_PREFIX` or `KOTODAMA_LAUNCH_SCOPED`: `for_the_user`), `app_name` (the desktop id, else the program's file name), `unit_name` (`app-kotodama-<app>-<pid>.scope`), `is_empty` (a cgroup's `cgroup.procs`), `pass_scope_prefix` (the Daemon gives Extensions `SCOPE_PREFIX` marked `KOTODAMA_LAUNCH_SCOPED`). `scope/linux.rs` is the Linux half: the D-Bus call and the `pre_exec` wait.
- `dbus.rs`: the small D-Bus client: `Bus::session`, `Bus::system`, `Bus::at` (a bus by its address), `Bus::user_manager` (the private socket), `call`, `read`, and for a service, as the system Extension's fake logind is, `wait_forever` and `reply`; `Call`, `Marshal`, `Message` (`is_signal`, `is_call`, `body`), `Unmarshal` (every basic type, `variant`, `array`, `align_struct`, `skip`: enough for `Properties.Get` and `GetAll`, in either byte order; `None`, never a panic, on malformed bytes), `Error`. `dbus/tests.rs` also holds the fake peer the scope tests use, and `Get`/`GetAll` replies written byte for byte from the D-Bus specification.
- `watch.rs` (feature `watch`): `Watcher::start` (settles on its own thread), `Watcher::new` (no thread), `Watcher::watch`; reads are never changes, left out of the kernel's watch (`EventKindMask::CORE`) and dropped where a platform reports them anyway; missing directories are watched through the deepest directory on their path that exists, removed or renamed ones are forgotten. `links_to` finds the symlinks on the way to each directory (the profiles a NixOS or home-manager switch replaces); `watch_locked` watches the directory each sits in, and `Watched::forget_relinked` has the directories behind one replaced watched again where the new link leads.
- `runtime.rs` (Linux): for compositors that start after the Daemon (see its docs). `dir` (`$XDG_RUNTIME_DIR`), `wait_for` (retries until something turns up in watched directories: an inotify watch, else a doubling backoff, reset by a change; used by `wayland::Display` and `kotodama-hyprland`), `wayland_sockets`, `pass_wayland_display` (gives launched programs and Extensions the `WAYLAND_DISPLAY` the Daemon lacks).
- `wayland.rs` (feature `wayland`, Linux; the Daemon, the clipboard Extension, and the system Extension's `Display`): `wayland/display.rs:Display` (`WAYLAND_DISPLAY`, else the `wayland-N` sockets in the runtime dir; `connect`, `wait`), `wayland/data_control.rs:DataControl` (binds ext-data-control, else wlr; `set_selection`), `DataControlHandler` (`selected`, `finished`), `delegate_data_control!`.
- `testing.rs` (feature `testing`, dev-dependencies only): the test harness the Bundled extensions and the Daemon share. `Spawned` runs an Extension over its stdio as the Daemon does (`added`, `removed`, `quiet`, `start_run`, `outcome`; `status`, the last status it sent, kept apart from what `recv` reads; killed on drop); `install`, `bundled` and `connect` set up a Daemon, in the test's process or its own, and a Front end on its socket; `front_end` makes one on a connection made already.
- `<module>/tests.rs`: each module's unit tests, beside it (`config/tests.rs`, `scope/tests.rs`, `wayland/display/tests.rs`, ...).
- `tests/watch.rs`: the watcher against the real file system.
- `tests/log.rs`: where `log!` goes, with and without a `log` logger installed.
- `tests/version.rs`: the crate's major.minor, and its requirement on `kotodama-protocol`, are the protocol version it speaks (`README.md`, which crates.io shows).
