# Code map

Where things are, so you can open the right file without searching. Read this
index, then the `CODEMAP.md` of the crate you work in, which lists its modules
and key symbols as `path:symbol`. Both are maintained by hand: fix a stale line
when you notice it. Terms are defined in [GLOSSARY.md](GLOSSARY.md); decisions
are in [docs/adr/](docs/adr/).

## Layout

- [`crates/kotodamad/`](crates/kotodamad/CODEMAP.md): the Daemon. Index, ranking, History, sessions, Extension host, socket server.
- [`crates/kotodama-protocol/`](crates/kotodama-protocol/CODEMAP.md): messages, framing, handshake and Wire formats shared by everything.
- [`crates/kotodama/`](crates/kotodama/CODEMAP.md): the `kotodama` CLI (`toggle`, `open`) that a compositor keybind runs, and `kotodama extension check|new` for Extension authors.
- [`crates/kotodama-qml/`](crates/kotodama-qml/CODEMAP.md): the Quickshell Front end, a Rust cdylib QML module (`Kotodama`) plus `qml/KotodamaMenu.qml`.
- [`crates/kotodama-extension/`](crates/kotodama-extension/CODEMAP.md): the runtime Rust Extensions are built on (handshake, reader thread, `SentItems`, config, launch, XDG dirs, directory watcher, waiting on `$XDG_RUNTIME_DIR`, and with feature `wayland` finding the compositor and data-control; the dev-only `testing` harness the Bundled extensions' and the Daemon's tests share). The Daemon uses its watcher and its Wayland module.
- [`crates/kotodama-ai/`](crates/kotodama-ai/CODEMAP.md): Bundled extension, Proposals: catalog Actions a model picks for a request in plain words, run once the user confirms.
- [`crates/kotodama-apps/`](crates/kotodama-apps/CODEMAP.md): Bundled extension, desktop apps from `.desktop` files.
- [`crates/kotodama-calculator/`](crates/kotodama-calculator/CODEMAP.md): Bundled extension, math, units, currency, dates.
- [`crates/kotodama-clipboard/`](crates/kotodama-clipboard/CODEMAP.md): Bundled extension, clipboard history.
- [`crates/kotodama-emoji/`](crates/kotodama-emoji/CODEMAP.md): Bundled extension, emoji (with skin tones) and symbols, typed or copied.
- [`crates/kotodama-folders/`](crates/kotodama-folders/CODEMAP.md): Bundled extension, git projects and scripts from configured folders.
- [`crates/kotodama-hyprland/`](crates/kotodama-hyprland/CODEMAP.md): Bundled extension, Hyprland's windows (from its event socket) and keyboard shortcuts, with the Shortcuts View.
- [`crates/kotodama-system/`](crates/kotodama-system/CODEMAP.md): Bundled extension, power and session through logind (D-Bus), and the windows of any compositor with wlr-foreign-toplevel-management, which step aside on Hyprland.
- [`crates/kotodama-web-search/`](crates/kotodama-web-search/CODEMAP.md): Bundled extension, the fallback: web searches for what nothing matches, and addresses opened.
- `e2e/`: end-to-end tests against headless sway (`e2e/run`, `e2e/lib.sh`, one dir per test).
- `nix/`: `package.nix` (the separate packages: core, Front end, one per Bundled extension, each building only its own crates on one shared dependencies derivation from crane; `full` and `withExtensions` put them together), `extensions.nix` (the Bundled extensions and whether home-manager installs each unasked), `gungraun-runner.nix` (pinned runner for the instruction-counting benches), `home-manager.nix` (also `frontEnd`: the `kotodama-menu` service running the ready Front end), `home-manager-extensions.nix` (its `extensions.<name>.enable` and `finalPackage`), `tests/` (NixOS VM, Hyprland VM, QML module and home-manager checks).
- `scripts/`: dev environment (`dev-env`, `dev-image`; `dev-env` publishes `KOTODAMA_DEV_PORTS` and passes `KOTODAMA_DEV_ENV`'s variables into the container), `demo` (`just demo`: headless sway, the Daemon and the Front end over VNC, in the flake's `demo` dev shell; the rest is in `demo/`), bench runners (`bench-run` for criterion, `bench-instructions` for gungraun, `bench-compare`, `bench-crates`), `path-deps` (a crate's workspace dependencies), `has-crates`, `qml-module`, style checks (`restyled-crates`: the crates that opted into the code-quality guide's tools; `fmt`: the nightly rustfmt for them, and with `--check` stable rustfmt for the rest; `self-imports`: `use foo::{self};` written as `use foo;`, run by `fmt`; `comments`: the comment check), `tests/` (script tests).
- `demo/`: what `just demo` runs beside the code: `config.toml` (Aliases, Quicklinks, folders, bookmarks), `seed.sh` (made-up projects and scripts), `shell.qml` (the menu over a background that shows what to try), `GUIDE.md` (every feature, opened by the `guide` Quicklink), `vnc-proxy.py` (greets Screen Sharing with the VNC password it insists on, which wayvnc lacks).
- `docker/`: the dev image for machines without Nix (`just image`).
- `examples/`: Extensions for authors to start from, each run by a test in `kotodama-protocol/tests/` and checked by `kotodama/tests/extension.rs`: `shell-extension/` (bash and jq, the widest), `python-extension/` (stdlib, JSON, a Live query and `status`), `typescript-extension/` (Node, the protobuf Wire format by hand).
- `docs/extensions.md`: the guide for Extension authors (the Manifest, lifecycle, Items, Actions, Live queries, Views, apps, config, compatibility, trust). `docs/protocol.md`: every message with an example, written from the pinned samples by `kotodama-protocol/tests/protocol_doc.rs`.
- `docs/adr/`: decisions, one file per ADR named for the area it governs. `docs/agents/`: how agents use issues, labels and domain docs. `docs/try-it.md`: `just demo` on macOS, installing on Hyprland with home-manager, the compositor support table, several menus at once, and the manual checks. `docs/packaging.md`: the layout, build and run-time dependencies for a distro package without Nix.
- Root: `flake.nix` (dev shell, `demo` shell (wayvnc, apps to find, git, tmux, lazygit, wl-clipboard, emoji font), packages (`default`/`kotodama-full`, `kotodama-core`, `kotodama-qml`, `kotodama-<name>`), `overlays.default`, `checks`; `rustfmt-nightly` for `scripts/fmt`), `justfile`, `Cargo.toml` (`[workspace.lints]`; no shared version), `clippy.toml`, `.config/rustfmt.toml` (the restyled crates' formatting), `release-please-config.json` and `.release-please-manifest.json` (one package per crate; the core's two linked), `GLOSSARY.md`.

## Where to change X

- **Protocol message or field**: `kotodama-protocol/src/{message,front_end,item,view}.rs`. A change that only adds (an optional field at the end of a type, a message, a variant) raises the minor version in `version.rs:PROTOCOL_VERSION`; anything else needs a new major version, which keeps the old one (ADR 0026). Mark a new field `#[serde(default, skip_serializing_if = "crate::version::unread::<MINOR, _>")]` and a new variant in its `Since` impl, then rerun `tests/layout.rs` with `KOTODAMA_BLESS_LAYOUT=1` to pin `tests/layouts/<version>.txt` and rewrite `kotodama.proto`, and `tests/protocol_doc.rs` likewise to rewrite `docs/protocol.md` (a new sample needs its words in `describe`). Update both ends: `kotodamad/src/daemon.rs`, `kotodama-qml/src/connection.rs`, the Extensions.
- **Ranking rule**: `kotodamad/src/daemon.rs:Candidate::rank`, `rank.rs` (Tiers), `history.rs` (Frecency, Learned choices), `kind_order.rs`. Add cases to `kotodamad/tests/ranking.rs`; add an ADR if it changes the order of precedence.
- **Bundled extension**: new `crates/kotodama-<name>/` with `manifest.toml` and a `version` of its own, built on `kotodama-extension`; add `<name>` to `nix/extensions.nix`, with whether home-manager installs it unasked, which gives it its package `kotodama-<name>` and its `extensions.<name>.enable`; make it a release-please package: `crates/kotodama-<name>` in `release-please-config.json` (with its `Cargo.lock` extra-file) and in `.release-please-manifest.json` (`scripts/tests/release-please-crates.sh` checks both); give it a `CODEMAP.md` and a line in the layout above.
- **e2e test**: new `e2e/<name>/test.sh` (plus `shell.qml`, reference `.png` if visual) using `e2e/lib.sh`; `just e2e <name>`, `just e2e --update` for images.
- **Bench**: `crates/<crate>/benches/*.rs` with a `[[bench]] harness = false` entry in its `Cargo.toml` (criterion). CI compares against the base commit. An instruction-counting one (gungraun, under Valgrind) is a bench target named `instructions`, which `bench-run` leaves out and `bench-instructions` runs.
- **Config key**: the `from_config` of the owner (`kotodamad/src/{history,empty_query,kind_order,keywords}.rs`), or an Extension's settings module for `[extensions.<name>]`; test in `kotodamad/tests/config.rs`. Home Manager options: `nix/home-manager.nix` (typed ones for every Bundled extension's table and the Daemon's own, checked by `nix/tests/home-manager-ai.nix` and `nix/tests/home-manager-options.nix`).
- **Front end QML**: `kotodama-qml/qml/KotodamaMenu.qml`; Rust-side state in `src/{lib,rows,views,variant}.rs`. Check `e2e/menu`, `e2e/smoke`, `e2e/views` reference images.
- **Reserved key**: `kotodama-protocol/src/shortcut.rs:RESERVED_SHORTCUTS`; the Daemon drops them in `kotodamad/src/reserved.rs`; list them for Extension authors in `docs/extensions.md`.
- **What the Daemon refuses from an Extension**: `kotodamad/src/discovery.rs:Found::new` (the Manifest), `daemon.rs:extension_message` (sending `ToExtension::Rejected`); mirror the rule in `kotodama/src/extension/check.rs:Seen::take` and list it in `docs/extensions.md`.
- **CLI**: `crates/kotodama/src/main.rs:parse`; `kotodama extension` in `crates/kotodama/src/extension.rs:parse`.

## Tests and checks

- Unit tests: in the restyled crates (`scripts/restyled-crates`), `#[cfg(test)] mod tests;` at the bottom of a module and the tests in a sibling `tests.rs` (`src/tests.rs` for `lib.rs`, `src/index/tests.rs` for `index.rs`); in the others, until their restyle, an inline `#[cfg(test)] mod tests { … }`.
- Integration: `crates/*/tests/*.rs`. Helpers shared between test or bench targets sit in `tests/support/` (`benches/support/` for benches only), included with `#[path]`; the Daemon's `common/` and `benches/{corpus,setup}/` are the older `mod.rs` form. Daemon: `kotodamad/tests/` (`common/` helpers, `fixtures/recorder`, `ranking.rs`, `interaction.rs`, `open_view.rs`, `views.rs`, `config.rs`, `forget.rs` (Forget, clearing, undo and its Toast offers), `reads_first.rs`: off-path indexing, hot Items and a property test against a full search; `kotodamad.rs`: the binary over its socket, incl. a Front end and an Extension recorded on protocol 1.0 and newer-major peers turned away). Protocol: `layout.rs` (per-version layouts and `kotodama.proto`), `handshake.rs`, `protobuf.rs` (prost reads the protobuf Wire format), `conformance.rs`, `protocol_doc.rs` (`docs/protocol.md`), `{shell,python,typescript}_extension.rs` (the examples). CLI: `kotodama/tests/extension.rs` (`kotodama extension check` and `new`). Bundled extensions and the Daemon share `kotodama-extension`'s `testing` feature (`Spawned`, Daemon setup, a Front end on its socket).
- e2e: `e2e/*/test.sh` under headless sway, which `e2e/run` gives a virtual keyboard for the whole run (without one, windows bind no keyboard and lose keys). `e2e/type-and-paste/client.qml` is the window typed into; it logs `ready` once it has the keys. `latency` runs on PRs only when what it builds on changed. `menu` runs a Late Result with Enter once a frame has shown it (its `shell.qml` logs the top row; the recorder fixture answers Live queries from `live.json`). `emoji` types an emoji in a configured skin tone, and a symbol, into a test client, searched in the Emoji app. `apps` runs the folders, calculator and emoji Bundled extensions: `projects` and Tab shows the chip, the intro card and the projects (a reference image, under a home of its own so the paths read `~/Projects`), typing filters, Backspace leaves and Enter on the entry Item enters again, Esc clears the text and stays in the app, then goes back to the search with the menu open, then clears the search's text before it closes the menu, the emoji show only in their app (`kotodama open --app`), and `15min in sec` is answered in the search and in the calculator's app (its `shell.qml` logs the scope, the intro, the query and each row's Extension). The `front-end` example's `--app` enters the app the query's first word names, for `clipboard`, `late-display` and `emoji`. `open-view` checks `kotodama open --view` shows the View in the first frame (its `shell.qml` logs the top View as the window maps). `views` checks list View filtering, that typing in a 1000-Item list View keeps the selected Item and never resets the model, and that no View change shows the search between two Views. `pointer` gives the seat a pointer for the test (`virtual-pointer.rs`, built with `rustc`) and checks a resting pointer leaves the top row selected while the rows change under it, and a moved one selects the row it lands on (its `shell.qml` logs the rows). `late-display` starts the Daemon and the clipboard Extension with no compositor in sight, then links the socket into their runtime dir. `type-and-paste` and `clipboard` wait for the Daemon's debug log `copied to the clipboard` before Ctrl+V. `confirm` runs an Action that asks first only on a second Enter, and checks Esc and typing drop the question (its `shell.qml` logs `confirming`). `undo` forgets a picked Result by its key and checks Ctrl+Z on the Toast puts it back in the same place. `problems` starts with a setting that isn't one: `kotodama check` lists it, the footer counts it (a reference image), a click on the count (the `pointer` test's `virtual-pointer.rs`) opens the list (another), and fixing the config clears it (its `shell.qml` logs `problems` and the top View's title). `system` finds two Quickshell windows by title through wlr-foreign-toplevel, focuses one and closes the other (`kotodamad`'s `front-end` example runs any Action with `--action <id>`), and lists the power Items without logind.
- Benches: in each crate's `benches/`, listed in its `CODEMAP.md`. `kotodamad/benches/instructions.rs` is the instruction-count gate CI runs on PRs (`scripts/bench-instructions`); the rest are criterion, run by `scripts/bench-run`.
- Nix: `nix/tests/vm.nix` (NixOS VM, `front-end.py`; its `switched` specialisation, switched to mid-test, installs apps and Extensions through the system and home-manager profiles), `nix/tests/hyprland.nix` (Hyprland in a NixOS VM with a virtio GPU: windows, shown once though the system Extension could list them too, binds, `--view hyprland/shortcuts`, the home-manager `frontEnd` service showing the menu), `nix/tests/qml-module.nix`, `nix/tests/home-manager-extensions.nix` (which Bundled extensions the module installs, and the warning for settings of one left off; `vm.nix` checks one left off isn't started); `flake.nix` `checks`.
- Script tests: `scripts/tests/*.sh`.

`just` recipes (all run in `scripts/dev-env`):
- `just check`: nixfmt, shellcheck, `just --fmt`, actionlint, `scripts/fmt --check` (stable rustfmt's defaults, the nightly rustfmt and no `use foo::{self};` for restyled crates), `just comments`, clippy `-D warnings` in two passes (libraries, binaries and examples; then tests and benches, which may unwrap).
- `just fmt`: formats the restyled crates (`scripts/restyled-crates`) with the nightly rustfmt and `scripts/self-imports`; touches no other crate.
- `just comments`: `scripts/comments` over the restyled crates.
- `just test`: script tests, `cargo nextest run --workspace`, doc tests.
- `just bench`: `cargo bench --workspace` (with the gungraun benches; Valgrind and `gungraun-runner` are in the dev shell).
- `just e2e [--update] [test...]`: `e2e/run`.
- `just demo [--keep]`: `scripts/demo`, Kotodama on headless sway over VNC on `localhost:5900` (run on the host; it enters the dev environment itself). `docs/try-it.md` documents it.
- `just shell`, `just image`.

CI (`.github/workflows/ci.yml`):
- On PRs, `changes` gates the jobs below by path (docs-only runs none; `bench` and `instructions` only for the crates `scripts/bench-crates` lists, lockfiles, scripts and CI; e2e `latency` for the crates the Daemon, `kotodama` and the QML module build on and the e2e harness; `nixos-vm` for crates, lockfiles, the flake and `nix/`); `ci` is the single required check, and waits for every job but `bench` (criterion timings are too noisy to hold a merge; `instructions` is the gate).
- On PRs, `linear` fails a branch with a merge commit: branches are rebased onto main, never merged with it.
- On PRs and main: `test` (check + test, x86 and arm), `e2e` (both arches; `latency` as gated above), `bench` (base vs this commit; fails on +50% time, +10% Daemon memory). On main, `bench` runs both commits on one runner and caches the results as `bench-results-<sha>`; a PR compares against its base's cached results with shorter criterion times, reruns the base on its own runner only when a timing fails, and runs both commits when nothing is cached. `instructions` (`scripts/bench-instructions`: base vs this commit on one runner; fails on +5% instructions). `nixos-vm` (the NixOS VM, Hyprland VM, QML module and home-manager checks; the packages' dependencies come from Cachix). `packages` (gated like `nixos-vm`: one `nix build` per released package, so each builds alone).
- Main only: `image` (dev image), cargo cache saves.
- `release-please.yml`: a release PR per package from the Conventional Commits that touch its path; tags `<package>-v<version>`.
